\section{Open-Loop and Closed-Loop Navigation}%
\label{sec:nav:principles}

\subsection{Principle of Open-Loop Navigation}%
\label{subsec:nav:openloop-principle}

In open-loop navigation, the complete path is resolved before the drone starts
moving. The planner takes as input a map of the environment, a start position,
and a target~\cite{kumar2025comprehensive}, then searches for the route that
minimises a chosen cost. That cost need not be distance: flight time, energy
consumption, the number of turns, or path smoothness are all used in
practice~\cite{kumar2025comprehensive}. Once the route has been obtained, the
vehicle executes it as computed.

This mode of operation is also known as offline planning, and it presupposes a
static environment~\cite{kumar2025comprehensive}. Where that assumption holds, it
offers a real advantage: the problem is solved once, on the ground, without the
computational constraints of the onboard hardware.

\subsection{Principle of Closed-Loop Navigation}%
\label{subsec:nav:closedloop-principle}

In closed-loop navigation, the decision is re-derived throughout the flight. The
drone observes its surroundings, updates its internal representation of them, and
selects its next action from that updated state. Online planning rests on the
same principle and is designed to accommodate unexpected obstacles and changing
conditions~\cite{kumar2025comprehensive}. Learning-based methods make this
structure explicit: the agent executes an action, the environment returns an
observation and a reward, and both are fed back into the following decision,
closing the loop~\cite{chang2023review}.

The benefit is robustness. Fixed waypoints and pre-computed paths adapt poorly to
conditions that evolve and to obstacles that were not anticipated, which raises
the risk of collision~\cite{pore2026uavqr}.



\section{Open-Loop Methods: Classical Algorithms}%
\label{sec:nav:classical}

Classical algorithms come from robotics and operations research, and they form
the first family in the standard taxonomy of trajectory design
methods~\cite{krayani2023goal}. They all share one assumption: the workspace is
known before the flight and does not change during the mission. The first four
methods search for a path inside a graph. The last two describe the mission as an
optimisation problem and solve it with a solver.

\subsection{Dynamic Programming}%
\label{subsec:nav:dp}

Dynamic programming is not really a competitor of the methods that follow. It is
the general principle behind several of them. The idea is to cut a large decision
problem into a series of smaller steps, solve each step one after the other, and
then build the global solution from these partial results.

For \glspl{abb:uav}, it has been used to build a trajectory that fits inside a
fixed mission time, and to choose in which order a drone should visit wireless
sensor nodes to collect data~\cite{krayani2023goal}. Its cost grows quickly with
the number of nodes, which makes it too slow for real time, and it works poorly
on fine grids, because more accuracy means more
computation~\cite{krayani2023goal}.

\subsection{Dijkstra's Algorithm}%
\label{subsec:nav:dijkstra}

Dijkstra looks for the shortest path between two points in a graph. It starts
from the departure point and explores the graph in all directions, like a circle
that grows, until this circle reaches the goal~\cite{chang2023review}. Because it
explores everything around the start, it always finds the shortest path.

It has been used to bring a drone to its target in the shortest time for a given
battery level~\cite{krayani2023goal}. Its advantages are that the result is
guaranteed, that it is simple to implement, and that it works in any
environment~\cite{kumar2025comprehensive}. Its drawbacks come from the same
behaviour: it is slow, it becomes expensive on large graphs, and it only works in
static environments~\cite{kumar2025comprehensive}.

\subsection{A* Algorithm}%
\label{subsec:nav:astar}

A* improves Dijkstra with one simple idea. Instead of exploring in all
directions, it also estimates how far each point still is from the goal, and it
explores first the points that seem closer to it~\cite{chang2023review}. The
search becomes directed instead of blind, so A* reaches the target after visiting
far fewer points, and it returns a path that is close to the best
one~\cite{kumar2025comprehensive}.

This gain has a price. A* uses a lot of memory in large environments, and the
quality of the result depends on the quality of the estimate it
uses~\cite{kumar2025comprehensive}. The path is also not smooth, because the
drone can only move towards a fixed set of neighbouring directions, which gives a
route with sharp turns~\cite{chang2023review}. Finally, A* returns a list of
waypoints, not a trajectory that the vehicle can directly
follow~\cite{krayani2023goal}.

\subsection{D* and Its Variants}%
\label{subsec:nav:dstar}

D* was created to remove the main weakness of the two previous methods. When the
map changes, it does not start again from zero. It only updates the part of the
path that is affected, and it keeps the rest~\cite{krayani2023goal}. This makes
it much faster when new obstacles appear in a cluttered environment.

It also works on maps that are not grids and keeps a low computation
time~\cite{kumar2025comprehensive}. On the other hand, it needs a good initial
path, it can become expensive in some situations~\cite{kumar2025comprehensive},
and it gives no guarantee on the quality of the result in a large environment
that keeps changing~\cite{krayani2023goal}. As explained in
\Cref{subsec:nav:closedloop-principle}, D* sits on the border of the open-loop
family: it starts from a complete path, like the other methods here, but it
corrects that path during the flight.

The next two methods work differently. They do not search inside a graph. They
write the mission as an optimisation problem and let a solver find the answer.

\subsection{Mixed-Integer Linear Programming}%
\label{subsec:nav:milp}

Linear programming looks for the minimum or the maximum of a linear function
under a set of linear constraints. This fits path planning well, because the goal
is often to minimise a distance, a time, or an
energy~\cite{kumar2025comprehensive}. Mixed-integer linear programming, or
\glsxtrshort{abb:milp}, extends this to problems that mix continuous values, such
as a position, with discrete choices, such as visiting a point or
not~\cite{kumar2025comprehensive}.

For a \gls{abb:uav}, the flight is cut into time steps, and each step describes
the state of the drone. The solver then returns a complete trajectory before the
mission starts~\cite{krayani2023goal}. This method is designed for offline
planning, and it has two known limits: the search has no guide, so it can get
stuck, and it does not work well for long trajectories in complex
environments~\cite{krayani2023goal}.

\subsection{Traveling Salesman Problem and Its Profit Variant}%
\label{subsec:nav:tsp}

The travelling salesman problem, or \glsxtrshort{abb:tsp}, is used when the
mission is not to reach one goal but to visit several places. The drone must pass
through a fixed set of points, visit each one only once, and come back to its
starting position before the battery runs out~\cite{krayani2023goal}.

The problem is NP-hard, which means that finding the exact best tour takes too
much time as soon as the number of points grows. In practice, two solutions are
used: local-search methods such as 2-OPT and 3-OPT, which improve a tour step by
step, or evolutionary algorithms~\cite{krayani2023goal}. The \gls{abb:tspwp} is a
version where each point also carries a reward, and the algorithm then looks for
the best compromise between the distance travelled and the reward
collected~\cite{krayani2023goal}. This is useful when some targets matter more
than others. Its main limit is being offline, so if a new target appears during the flight, the whole tour must be
recomputed from the beginning~\cite{krayani2023goal}.

Behind their differences, these methods share the same limitation. All of them
need a description of the workspace before the flight, as a graph, a grid, or a
list of targets with known costs. 
Even D*, the most flexible of the six, still starts from a complete path and only
repairs it. The next section presents a second group of open-loop methods. They
keep the same assumption, but they replace exact search with stochastic
optimisation.

\section{Open-Loop Methods: Biologically Inspired Algorithms}%
\label{sec:nav:metaheuristics}

The previous section ended on a difficulty: the \glsxtrshort{abb:tsp} is NP-hard,
so exact solutions become impossible to compute as soon as the number of targets
grows. One of the two answers proposed in the literature is to use evolutionary
optimisation algorithms, which have proved effective at reducing the total
distance travelled in real cases~\cite{krayani2023goal}. This is the second
family of open-loop methods.

These algorithms take their inspiration from the collective behaviour of natural
systems, where a group of simple agents interacts to solve a problem
together~\cite{kumar2025comprehensive}. They do not compute the best solution,
they search for a good one. A population of candidate solutions is generated,
evaluated, and improved over many iterations, until the result stops getting
better. They are useful when the optimal solution is hard to define in advance,
but they give no guarantee of optimality~\cite{kumar2025comprehensive}.

\subsection{Genetic Algorithm}%
\label{subsec:nav:ga}

The genetic algorithm follows the principle of natural selection. A population of
candidate paths is created, each one is scored, and the best ones are used to
produce the next generation through selection, crossover, and
mutation~\cite{kumar2025comprehensive}. Over the generations, the population
moves towards better routes.

For \glspl{abb:uav}, the genetic algorithm has been used to obtain a suitable
path, in particular in target-coverage problems~\cite{krayani2023goal}. Its main
weakness is speed: convergence is slow, which makes it inefficient for path
planning problems that need a fast answer~\cite{krayani2023goal}, and this
becomes a real obstacle in real-time scenarios~\cite{kumar2025comprehensive}.

\subsection{Particle Swarm Optimization}%
\label{subsec:nav:pso}

Particle swarm optimisation is inspired by the movement of bird flocks. Each
particle represents a candidate solution and moves through the search space under
two influences: the best position it has found itself, and the best position
found by the whole swarm. Step by step, the swarm concentrates around the
promising regions.

It is widely used in \gls{abb:uav} path planning~\cite{kumar2025comprehensive}
and is good at local optimisation, which is why it is often combined with a
genetic algorithm, the latter handling the global search~\cite{krayani2023goal}.
Two limits are reported. Standard versions converge too early and explore a
limited part of the space~\cite{kumar2025comprehensive}, which means the swarm
can settle on a solution that is not the best one. Variants have been proposed to
correct this, for example by keeping the population diverse, or by encoding the
motion of the vehicle directly in the particles in order to follow dynamic
targets~\cite{kumar2025comprehensive}.

\subsection{Ant Colony Optimization}%
\label{subsec:nav:aco}

Ant colony optimisation copies the way ants find the shortest route between their
nest and a food source~\cite{kumar2025comprehensive}. Artificial ants build
candidate paths, and each one leaves a pheromone trail on the route it used.
Short routes receive more pheromone, so they attract more ants in the next
iteration, while the pheromone on the other routes slowly evaporates. The colony
converges on a good tour without any central decision.

The method is effective for \gls{abb:uav} path planning, and it has been applied
to low-altitude planning, to multi-\gls{abb:uav} missions, and to coverage
planning~\cite{kumar2025comprehensive}. Its cost is the main drawback: it needs a
large amount of data to find the optimal solution, its iterations are slow, and it
requires much more simulation time than the other two~\cite{krayani2023goal}. It
also struggles with local optima in complex
scenarios~\cite{kumar2025comprehensive}.

None of the three dominates the other two, and the literature suggests that
combining them may be necessary to solve \gls{abb:uav} path planning
effectively~\cite{krayani2023goal}. This is why hybrid schemes are common, the
most frequent one pairing a genetic algorithm for the global search with particle
swarm optimisation for local refinement~\cite{krayani2023goal}.

These methods remove the scalability barrier of the exact algorithms, but they do
not remove the assumption behind them. They are optimisers, not decision loops:
the candidate solutions, the cost function, and the set of targets must all be
defined before the search starts. Variants designed for dynamic targets exist,
yet they still re-optimise a model that is given in advance. 

\section{Limits of Open-Loop Methods}%
\label{sec:nav:openloop-limits}

The two families presented above differ in the way they search for a solution.
Classical algorithms explore a graph or solve an exact optimisation problem,
while biologically inspired algorithms replace this exact search with a
population that improves over iterations. They do not differ, however, in what
they assume before the search starts. Four limits follow from that shared
assumption.

\begin{itemize}[itemsep=0.5em]
    \item \textbf{The environment must be known in advance.} Path planning begins
          with a model of the environment, in which the obstacles are already
          identified, and with a start point and a target that are already
          fixed~\cite{kumar2025comprehensive}. Whatever form this model takes, a
          graph, a grid, or a list of targets with their costs, it has to exist
          before the flight.
    \item \textbf{The plan does not adapt during the mission.} Offline planning
          assumes a static environment~\cite{kumar2025comprehensive}, so a route
          computed on the ground stays valid only as long as nothing changes.
          Fixed waypoints and pre-computed paths are poorly suited to conditions
          that evolve and to obstacles that were not known in advance, and this
          increases the risk of collision~\cite{pore2026uavqr}.
    \item \textbf{Replanning is expensive.} When something does change, most of
          these methods have to start again. With the \glsxtrshort{abb:tsp}, the
          appearance of a single new target forces the whole tour to be
          recomputed from the beginning~\cite{krayani2023goal}. D* is the
          exception, since it repairs only the affected part of the
          path~\cite{krayani2023goal}, but even D* needs a complete initial path
          to repair.
    \item \textbf{Coordination between drones is decided before take-off.} In a
          multi-\gls{abb:uav} mission, the targets have to be assigned and the
          workload balanced~\cite{kumar2025comprehensive}. With an open-loop
          scheme, this assignment is part of the plan computed on the ground.
          Allocation systems able to learn and adapt to environmental changes in
          real time are presented in the literature as a future direction, not as
          current practice~\cite{kumar2025comprehensive}.
\end{itemize}

These four limits are not independent. They all follow from the same requirement, namely that the environment be described before the flight. They therefore apply together whenever the layout is discovered during the mission, whenever obstacles move, or whenever new targets appear while the drone operates

The next sections therefore turn to the closed-loop methods, which recompute the
decision as new observations arrive. \Cref{sec:nav:learning} presents the
learning-based approaches, \Cref{sec:nav:activeinf} active inference, and
\Cref{sec:nav:genai} the recent use of language and vision-language models.

\section{Closed-Loop Methods: Learning-Based Approaches}%
\label{sec:nav:learning}

Learning-based methods form the third family in the standard
taxonomy~\cite{krayani2023goal}. They replace the explicit optimisation of the
previous sections with a policy learned from interaction. The structure is a loop
with four elements: an agent, an environment, an action, and a reward. The agent
performs an action, the environment returns a new state and a reward, and both
feed back into the next decision~\cite{chang2023review}.

The problem is usually written as a Markov decision process, or as its partially
observable version, the \glsxtrshort{abb:pomdp}, when the drone cannot observe
the true state of the world. A \glsxtrshort{abb:pomdp} is defined by the tuple
$\langle S, A, T, R, O, Z, \gamma \rangle$, where $S$ is the set of states, $A$
the set of actions, $T$ the transition probabilities, $R$ the reward, $O$ the set
of observations, $Z$ the observation probabilities, and $\gamma$ the discount
factor~\cite{sandino2020autonomous}. Since the state is hidden, the agent
maintains a \emph{belief state}, a probability distribution over all possible
states, updated from the history of actions, observations, and
rewards~\cite{sandino2020autonomous}:

\begin{equation}
    b(h) = \bigl( \prob[S_t = s^1 \mid H_t = h], \; \dots,
    \; \prob[S_t = s^n \mid H_t = h] \bigr)
    \label{eq:nav:belief}
\end{equation}

The objective is then to find the policy $\pi$ that maps a belief to an action
and maximises the discounted accumulated reward~\cite{sandino2020autonomous}:

\begin{equation}
    \pi^* = \argmax_{\pi} \; \esp_{\pi}\!\left[
        \sum_{t=0}^{\infty} \gamma^t R_t \right]
    \label{eq:nav:policy}
\end{equation}

The discount factor $\gamma \in [0, 1]$ controls how far into the future the
agent looks. The methods below differ in how they compute or approximate this
policy.

\subsection{Q-Learning}%
\label{subsec:nav:qlearning}

Q-learning is the simplest of these methods. Instead of learning a policy
directly, it learns a value $Q(s, a)$ for every state--action pair, which
represents the expected return of taking action $a$ in state
$s$~\cite{chang2023review}. The values are stored in a table and updated at each
step:

\begin{equation}
    Q(s_t, a_t) \leftarrow Q(s_t, a_t) + \alpha \Bigl[ r_t
    + \gamma \max_{a'} Q(s_{t+1}, a') - Q(s_t, a_t) \Bigr]
    \label{eq:nav:qlearning}
\end{equation}

In \gls{abb:uav} work, Q-learning has been used for trajectory design, for
example to maximise the sum-rate, the quality of experience, or the fairness of
user coverage in wireless networks~\cite{krayani2023goal}. Its main weakness is
the speed of learning: each step produces a single update of the table, and the
algorithm cannot explain why an action was wrong, which slows down
convergence~\cite{krayani2022novel}.

\subsection{Deep Q-Networks and Their Variants}%
\label{subsec:nav:dqn}

Deep Q-networks replace the table by a neural network, which allows the method to
work with high-dimensional inputs such as images or maps. One example applies a
Double Deep Q-Network with two convolutional models, fed at the same time with a
local map around the drone and with the global map, the first handling collision
avoidance and the second the general direction~\cite{chang2023review}.

Two mechanisms make training possible. Past transitions are stored and replayed
in mini-batches, which breaks the strong correlation between successive samples,
and reusing this past experience reduces the amount of data needed to train the
model~\cite{ding2024external}. Even with these mechanisms, the method still
requires a large number of samples, and it remains limited to discrete actions.

\subsection{Policy-Gradient and Actor-Critic Methods}%
\label{subsec:nav:policygradient}

Policy-gradient methods optimise the policy directly instead of learning a value
table, which makes them suitable for continuous actions such as a velocity or a
heading. They use two networks: an actor that produces the action from the
current state, and a critic that estimates the value of that
action~\cite{ding2024external}.

\Glsxtrfull{abb:ddpg} follows this structure and has been used for continuous
\gls{abb:uav} trajectory optimisation~\cite{ding2024external}. Training is
unstable by nature, so target networks are added and updated slowly through a
soft update rule, which keeps them behind the main networks and stabilises the
process~\cite{ding2024external}.

\subsection{Multi-Agent Reinforcement Learning}%
\label{subsec:nav:marl}

Multi-agent reinforcement learning extends this framework to several drones
acting in the same environment. Each agent has its own local actor-critic
network, selects its action from its own local state, and receives a global
reward that measures the performance of the whole
system~\cite{ding2024external}. Because the agents are fully decentralised, no
central coordinator is needed, which simplifies the architecture and reduces the
communication overhead~\cite{ding2024external}.

Hybrid schemes combine several algorithms when the decisions are of different
types. One framework uses a multi-agent actor-critic for the discrete part of the
problem and \glsxtrshort{abb:ddpg} for the continuous
trajectory~\cite{ding2024external}.

\subsection{Hierarchical Reinforcement Learning}%
\label{subsec:nav:hrl}

Hierarchical reinforcement learning decomposes a long mission into a hierarchy of
sub-tasks, each governed by its own policy. A high-level policy decides which
sub-task to execute, and a low-level policy executes it until a termination
condition is reached. The aim is to handle long-horizon missions, where a single
flat policy would need too many steps to learn anything useful.

\subsection{Online POMDP Solvers}%
\label{subsec:nav:pomdp-solvers}

Online \glsxtrshort{abb:pomdp} solvers belong to the same decision framework but
do not learn a policy. They compute the next action directly during the flight,
by running Monte Carlo simulations from the current belief and selecting the
action with the best estimated value. The Adaptive Belief Tree follows this
principle and has been used for autonomous navigation in cluttered,
\gls{abb:gps}-denied environments, where sensor noise and occlusion prevent the
drone from observing the true state~\cite{sandino2020autonomous}.

This avoids the training phase entirely, but it moves the cost to the flight
itself. Running an expensive decision algorithm together with object detection on
the limited onboard hardware of a small drone is identified as an open
challenge~\cite{sandino2020autonomous}.

\subsection{Limits of Learning-Based Approaches}%
\label{subsec:nav:learning-limits}

Four limits are reported across this family.

\begin{itemize}[itemsep=0.5em]
    \item \textbf{Training cost.} Once the network is trained, a solution is
          produced quickly, but training itself requires a large number of
          samples and several epochs, which takes considerable
          time~\cite{krayani2026bayesian}.
    \item \textbf{Poor generalisation.} Most machine learning and reinforcement
          learning methods cannot adapt to situations that were not part of their
          training set. Adapting them requires extensive retraining, which is a
          problem for real-time
          decision-making~\cite{krayani2023goal, krayani2026bayesian}.
    \item \textbf{Onboard computation.} Decision-making and perception must run
          together on hardware with limited resources, and this remains an open
          difficulty~\cite{sandino2020autonomous}.
    \item \textbf{Reward design.} The behaviour of the agent depends entirely on
          the reward function, which has to be designed by hand. A typical
          formulation combines several weighted objectives with penalty
          terms~\cite{ding2024external}, and these weights must be tuned for each
          mission.
\end{itemize}



\section{Closed-Loop Methods: Active Inference}%
\label{sec:nav:activeinf}

Active inference comes from neuroscience. The starting idea is that the brain
does not passively receive information: it constantly predicts what it is about
to perceive, and it reacts when reality does not match the prediction. This
behaviour can be described by a single rule, the minimisation of what is called
free energy~\cite{ding2024external}. Researchers in robotics then reused this
rule to control machines~\cite{ji2023delay}.

To understand what changes compared with the previous section, it helps to
compare the two. A reinforcement learning agent learns because the environment
gives it a reward, and its whole behaviour depends on that
signal~\cite{ding2024external}. An active inference agent receives no reward. It
carries inside itself a model of the world, that is, an expectation of what it
should observe. Its only objective is to reduce the difference between this
expectation and what its sensors actually report. This is why the framework is
often described as a filter plus a controller~\cite{ji2023delay}.

\subsection{The Free Energy Principle}%
\label{subsec:nav:fep}

The principle says that an agent builds a model of its environment from what its
sensors measure, and then acts so that its observations stay close to what it
expects~\cite{ji2024integration}.

When a difference appears between the model and reality, the agent has two ways
of reducing it. It can change its mind, which means updating its beliefs to match
the observations. Or it can change the world, which means moving or acting so
that the observations match the model again. The two mechanisms work together in
a loop: what the agent believes determines what it does, and what it does changes
what it observes~\cite{ji2024integration}.

Ideally, the agent should minimise its \emph{surprise}, meaning how unexpected
its current observation is. This cannot be computed in practice, because it would
require considering every possible cause of that
observation~\cite{ji2024integration}. This is why the framework uses two
quantities that can actually be computed: one for understanding the present, one
for choosing the future.

\subsection{Variational Free Energy}%
\label{subsec:nav:vfe}

Variational free energy is used to answer the question ``where am I and what is
happening around me?''.

The difficulty is that the drone cannot know the true state of the world, only
what its sensors show. The exact answer cannot be computed, so an approximate one
is used instead, written $q(z_t)$, and the agent brings it as close as possible
to the truth~\cite{ji2024integration}. Free energy measures this remaining
distance:

\begin{equation}
    F_{\text{AIF}} = D_{\mathrm{KL}}\bigl( q(z_t) \,\|\, p(x_t \mid y_t) \bigr)
    - \ln p(y_t, a_t)
    \label{eq:nav:vfe}
\end{equation}

The first term is a mathematical distance between what the agent believes and the
best possible explanation of its observations. The second is the quality of the
model itself.

This single quantity plays two roles. If the agent minimises it by changing its
beliefs, it is doing perception. If it minimises it by changing its actions, it
is doing control~\cite{ji2024integration}. In both cases, the effect is the same:
the model explains the observations better. In practice, free energy works like
the loss function of a neural network, a number that the system tries to push
down~\cite{ji2024integration}.

\subsection{Expected Free Energy}%
\label{subsec:nav:efe}

Variational free energy only looks at the present. It says nothing about which
action to take next, because it uses observations the agent has already
received~\cite{ding2024external}. To plan ahead, the framework uses a second
quantity, the expected free energy. For each possible action, the agent imagines
what would happen, computes the free energy that this action would produce, and
then chooses the action with the lowest value.

The interesting part is what this quantity contains. When a drone minimises
expected free energy, it selects actions that combine two behaviours at once:
gathering information about the environment, and moving towards its
objective~\cite{wang2026bridging}. The formula shows these two behaviours as two
separate terms~\cite{fang2024resource}:

\begin{equation}
    \begin{aligned}
        G_{\text{AIF}} = {} & \underbrace{-\,\esp_{q(o_t)}\bigl[
            D_{\mathrm{KL}}\bigl[ q(s_t \mid o_t) \,\|\,
                q(s_t \mid s_{t-1}, a_{t-1}) \bigr]
        \bigr]}_{\text{belief error}}                                  \\[0.4em]
                            & \underbrace{-\,\esp_{q(o_t)}\bigl[
            \log p(\tilde{o}_t) \bigr]}_{\text{preference}}
    \end{aligned}
    \label{eq:nav:efe}
\end{equation}

The first term is high when an action would teach the agent something new, so it
pushes towards exploration. The second term is high when an action brings the
agent closer to the situation it wants, so it pushes towards the
goal~\cite{fang2024resource}.

This is the main attraction of the framework. In reinforcement learning,
exploration usually has to be added by hand, through an extra bonus in the
reward. Here, it comes out of the same equation as the goal.

\subsection{Active Inference for UAV Systems}%
\label{subsec:nav:aif-uav}

Several \gls{abb:uav} applications of this framework have been reported.

\begin{itemize}[itemsep=0.5em]
    \item \textbf{Resource allocation and anti-jamming.} Active inference has
          been applied to spectrum allocation for a drone facing a jammer. The
          reported advantage is speed of learning: the agent makes several
          updates at each step and can identify why an action was wrong, whereas
          Q-learning makes a single update without that
          information~\cite{krayani2022novel}.
    \item \textbf{Goal-directed trajectory design.} A model of the world is built
          before the mission from solved instances of the travelling salesman
          problem with profits. The drone then uses this model to infer its route
          when it meets a new situation. The method is reported as faster, more
          stable, and better at generalising than
          Q-learning~\cite{krayani2023goal}. The same principle has been used for
          anti-jamming trajectories, with an expert optimiser producing the
          training examples~\cite{krayani2026bayesian}.
    \item \textbf{Deep active inference.} For more complex tasks, neural networks
          are used to approximate the probabilities involved in free energy,
          which extends the framework beyond small
          problems~\cite{ding2024external}.
    \item \textbf{Low-level control.} Active inference has also been used to make
          a quadrotor follow a trajectory, acting as a state estimator combined
          with a controller. A variant handles the delay between a command and
          its effect, which improves accuracy~\cite{ji2024integration}.
    \item \textbf{Multi-UAV coordination.} Recent work places free-energy-based
          inference inside the decision nodes of behaviour trees, so that several
          drones can update their policies during the mission and adapt to each
          other~\cite{wang2026bridging}. Active inference has also been proposed
          for trajectory design in \gls{abb:uav}
          swarms~\cite{arshid2024active}.
\end{itemize}

\subsection{Limits of Active Inference}%
\label{subsec:nav:aif-limits}

Four limits appear in this literature.

\begin{itemize}[itemsep=0.5em]
    \item \textbf{The model of the world must be built first.} The agent cannot
          infer anything without an internal model of its environment. In the
          trajectory design work, this model is learned before the mission from
          examples produced by an expert
          optimiser~\cite{krayani2023goal, krayani2026bayesian}. The difficulty
          is therefore moved, not removed.
    \item \textbf{The exact computation is impossible.} The true state of the
          world cannot be computed directly, so the framework always works with
          approximations, and in practice assumes that the distributions are
          Gaussian~\cite{ji2024integration}.
    \item \textbf{Scaling up requires neural networks.} Applying the framework to
          complex tasks means approximating free energy with neural
          networks~\cite{ding2024external}, which brings back part of the
          training cost that active inference was supposed to avoid.
    \item \textbf{Multi-agent use is still rare.} The framework works well for a
          single agent, but its use for coordinating several drones remains
          limited, and existing frameworks are often centralised, which makes
          them hard to integrate into modular
          architectures~\cite{wang2026bridging}.
\end{itemize}
